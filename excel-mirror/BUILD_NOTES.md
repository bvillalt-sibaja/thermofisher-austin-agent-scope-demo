# Excel mirror — build notes

No real Microsoft Excel is installed on this Mac, so this is a genuine app build
(Tkinter), not just seed files. Word.app IS installed, so the Word step just gets
a real .docx (no mirror app).

## Launch
```
python3 main.py "<path-to-workbook.xlsx>" [--sheet SHEET_NAME]
```
Opens a green-ribbon, Excel-styled grid (column letters/row numbers, formula bar
showing the selected cell's reference + value). Click a cell to select it, double-click
(or type in the formula bar + Enter) to edit. Ctrl+H or the toolbar button opens a
functional Find & Replace dialog (Find Next selects the matching cell; Replace
overwrites it). Ctrl+S / Save button writes back to the same file with openpyxl.
Verified: headless model round-trip (get/set/find/save), and a real `python3 main.py`
launch confirmed exactly 1 OS window via `osascript`/System Events, no errors.

## Driving it programmatically (recommended for the automation)
`api.py` in this same directory exposes the model without any UI, for a `Start
Process`/direct-Python automation step, or just import `workbook.WorkbookModel`
directly (0-indexed row/col == 1-indexed openpyxl; grid (0,0) is cell A1):
```python
from workbook import WorkbookModel
m = WorkbookModel("<path>.xlsx")
m.get_ref("C2")                  # read a cell by A1-style ref
m.set_ref("C2", "A42362")        # write a cell
m.find_next("A42362")            # -> (row, col) 0-indexed, or None; row-major, wraps once
m.save()                         # writes back to the same path
```
Or from the CLI: `python3 api.py "<path>.xlsx" find "A42362"` / `get C2` / `set C2 value` / `save`.
If driving the actual GUI (image/click automation) instead, Find & Replace is a real
Toplevel dialog with entries + "Find Next"/"Replace"/"Close" buttons — same behavior
as Excel's, just simpler chrome.

## Visual fidelity + real cell formatting (2026-08-26 update)
Reskinned closer to real Excel: dark-green title bar + tab strip (File/Home/
Insert/... — Home active), a proper Home ribbon with Clipboard/Font/Alignment/
Editing groups, gray column/row headers that highlight the selected cell's row
and column, thin real gridlines, Calibri-family fonts, a green selection border.

The ~10 previously-decorative cosmetic steps ("Select Fill Color", "Merge &
Center", "All Borders", "Thick Outside Borders") are now real, backed by new
`WorkbookModel` methods (all additive — no existing method signature changed):
```python
m.set_fill(row, col, "FFC000")                 # 6-hex RGB; alpha is handled for you
m.get_fill(row, col)                            # -> 8-char ARGB string or None
m.set_border(row, col, style="thin"|"thick", sides=("top","bottom","left","right"))
m.set_border_range(r1, c1, r2, c2, style=..., outline_only=True|False)
m.merge_and_center(r1, c1, r2, c2, value=None)  # merges + centers; value optional
m.merged_ranges()                                # -> [(r1,c1,r2,c2), ...] 0-indexed
m.has_border(row, col)                           # -> bool
```
**Gotcha worth knowing:** openpyxl's `PatternFill(fgColor=rgb)` silently defaults
the alpha channel to `00` (fully transparent) if you pass a plain 6-char RGB hex
string instead of 8-char ARGB — the fill *looks* set (`fill_type` is `"solid"`)
but renders invisible in real Excel. `set_fill()` always prepends `FF` alpha
internally; call it, don't build `PatternFill` directly.

Applied to the seed files (`generate_seed_files.py`, formatting-only — never
touches a cell's position or value, so it can't break `find_row_by_value`/the
first-empty-row fallback the orchestrator's row-placement logic depends on):
- **Production Tracker**: pale-yellow (`FFFF99`) fill on the whole Notes column
  (closest analog to the recording's "Fill Color RGB in Description" — this
  sheet has no literal Description column), thin borders across the data block,
  thick outside border around it, and a merged/centered banner in columns H:I
  (past the used A-F columns, so it can never collide with automation-read cells).
- **CSAB**: amber (`FFC000`) "at risk" fill on the Group cell of the 97%-archive
  row (matches "Select Color Fill in Group"), same border treatment, merged/
  centered banner in columns K:L.
Verified by reloading both files fresh from disk after `generate_seed_files.py`
(not from in-memory state) and confirming `get_fill`/`has_border`/`merged_ranges`
all read back correctly, and that the existing data cells (P/N#, SKU, etc.) are
byte-identical to before.

`api.py`'s contract (`get_cell`/`set_cell`/`find_and_replace`/`save`) and
`orchestrator.py`'s existing calls (`get`/`set`/`find_next`/`find_row_by_value`/
`save`/`ExcelMirror(master, path, sheet=None)`/`.model`/`.refresh_grid()`) are
all unchanged and re-verified passing after this update.
